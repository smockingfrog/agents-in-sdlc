GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行されるツール操作やファイルの編集を確認できます。差分をインラインでレビューし、変更ごとに適用または却下して、エディターを離れずに追加プロンプトを送り、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして適用します。
- セッションの途中でエージェントに指示を追加し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいという依頼がありました。新しい会話を最初から始めずに、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作付きでチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、ツールの操作を確認します。ファイルの読み取りと編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - 変更を適用するには **Keep** を選択します。
   - 変更を元に戻し、もう一度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** 表示を開くと、このセッションで変更されたファイル全体を確認できます。

> [!NOTE]
> ツールの実行 (たとえば、ターミナル コマンド) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードを実装するまで待ちます。完了すると、変更内容の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。会話を継続するため、エージェントは前の作業のコンテキスト (変更したコンポーネント、スタイルの方針、設定を local storage に保存する方法など) を保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは直前の変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラスト モードと同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方針 (たとえば、好みに合わない方法でトグル UI をリファクタリングするなど) に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のメッセージを送信します。

> [!TIP]
> 実行中のセッションに指示を追加すると、最初からやり直すよりも速く調整できます。追加プロンプトで「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」のような変更を依頼したり、「トグルを3つにせず、ライト モードを既存の設定パネルに統合する」のように方向を修正したり、「両方のトグルにキーボード ショートカットを追加する」のように範囲を広げたりできます。

## 作業ファイル一式をレビューする

変更をコミットする前に、エージェントが触れたすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル一覧を確認します。Astro コンポーネント、スタイル、関連テストなどに更新があるはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して指示を追加しました。ファイルの編集を確認し、変更を適用または却下し、コンテキストを保ったまま追加プロンプトを送り、作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を適用または却下しました。
- 追加プロンプトでセッションの途中に指示を加えました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが作成した変更をレビューします。
